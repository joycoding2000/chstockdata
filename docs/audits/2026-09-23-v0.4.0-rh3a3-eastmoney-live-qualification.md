## 1. 失败点与实际调用链

真实失败用例是消费者 `tests/qualification/test_chstockdata_etf_gate.py::TestLiveEtfQualification::test_live_tradability_adjustment_and_freshness`，在 `assert tradability.is_success` 首次检查 `XSHG:510300`、资格会话日 `2026-09-11` 时停止。后续 corporate actions、bars/freshness 断言没有在此用例中执行，不能记为这项用例通过。

调用链：`live_provider()` → `ChStockDataProvider.fetch_tradability()` → `LibraryChStockDataClient.suspension()` → 已安装包 `chstockdata.get_suspension_info()` → structured `fetch_suspension_info()` / 全市场日期快照 → `a_stock._suspension_snapshot_page()` → `_em_get()` → Eastmoney HTTP GET。单次完整快照按日期缓存；第一次失败后对同一日期的消费者映射读取失败快照，不伪装成新的 provider fetch。

请求 endpoint 为 `https://datacenter-web.eastmoney.com/api/data/v1/get`。必要非敏感参数：`reportName=RPT_CUSTOM_SUSPEND_DATA_INTERFACE`、`columns=ALL`、`filter=(MARKET="全部")(DATETIME='2026-09-11')`、`pageSize=500`、`pageNumber=1`、`sortColumns=SUSPEND_START_DATE`、`sortTypes=-1`、`source=WEB`、`client=WEB`；超时 15 秒。`_em_get()` 最多执行两次请求，复用一个 `trust_env=False` 的直连 session。请求代码没有对单只 ETF 作服务器端过滤，成功取得完整市场快照后才会按证券代码匹配。

## 2. 双版本真实请求证据

复用 RH3-A.1 两个独立 Python 3.12.14 安装环境：A 为冻结 0.3.0，B 为原 0.4.0 wheel。测试均在隔离消费者副本中运行，导入路径位于各自 venv 的 `site-packages`。在各进程内只包裹真实 session 的 `get` 记录 endpoint、参数、响应状态或异常类型，仍执行原始网络调用；未替换响应、提供 stub 或改变断言。先调用真实 `get_suspension_info`，用消费者原有 JSON 解析边界读取其状态，再调用真实 `fetch_tradability`。两环境分别使用独立 cache 与 RH3-A.2 保留的 vipdoc 输入。

| HTTP 尝试 2 | `requests.ConnectionError`，约 94 ms | `requests.ConnectionError`，约 140 ms |

独立执行 `pytest -q tests/qualification/test_chstockdata_etf_gate.py -k test_live_tradability_adjustment_and_freshness`，两环境各为 **1 failed、16 deselected**，同样在第 248 行的 `tradability.is_success` 断言失败。RH3-A.2 的完整 live 组曾两次实测两版本各 **4 passed、1 failed**，唯一失败为此用例；本轮定向结果再次复现。RH3-A.2 全仓离线/契约/Golden/PIT/snapshot-replay 结果保持两版本各 **929 passed、5 skipped**；本轮未改代码或冻结证据，故没有把这项网络失败按测试通过处理。

**归因：** 当前资格主机到该 Eastmoney endpoint 的直连请求在 HTTP 响应前失败，属于本轮 `external dependency failure`。证据只支持“从该主机此时不可达”，不能断言 Eastmoney 服务在其它网络全局宕机，也不能据两版共同失败宣布停牌能力通过。未发现 0.4.0 特有接口回归；没有证据要求修改包或重建候选。若未来取得 HTTP 响应后出现结构或映射失败，需要重新诊断，不能套用本次归因。

## 3. 历史日历的运行前提

RH3-A.2 使用既有官方通达信 `https://data.tdx.com.cn/vipdoc/hsjday.zip` 的隔离刷新数据；归档 SHA-256 `72bf25fb6dd5fbdb1a83c64a37d8ad7c4d9652f7036919b6694ba955b643e968`，源 HEAD 的 `Last-Modified` 为 `Tue, 22 Sep 2026 07:56:47 GMT`。保留的可复现完整树是 `D:\Dev\Projects\chstockdata\.rh3a2-vipdoc`；其 `sh/lday/sh000001.day` 当前 SHA-256 为 `7eeedb6c1691304f21636a88af84730107074b8072c5fb265b8f4098ea28da0c`。另有同哈希的五文件最小副本位于 RH3-A.2 报告列出的隔离目录。

本轮重新解析 8,731 个指数交易日，覆盖 1990-12-19 至 2026-09-22；在资格日期 2026-09-23，末 bar 仅落后 1 天，配置 freshness 阈值为 5 天，故结构化日历路由只尝试并选取 `tdx_vipdoc:index_bars`，`stale=false`、`partial=false`。RH3-A.2 的 2015-01-05 至 2022-12-30 真实消费者请求因此成功；这个通过依赖已经刷新且可读的本地文件，不保证任意安装环境自动具有相同历史覆盖。库存再次过期时，路由可能回退到固定 2,000 根在线日线；该窗口不能称为完整历史日历。

## 4. Owner 风险处置与停止结论

1. **保留 live gate 为未关闭并稍后复测。** 在具备 Eastmoney 直连能力的受控资格主机，使用同一候选 wheel、冻结消费者契约和已记录的 vipdoc 输入，重跑五项真实 live 资格测试，并记录网络/HTTP、provider 与消费者结果；只有真实通过才形成最终 Consumer Qualification PASS 候选。
2. **调查资格主机的直连出站路径。** 由环境所有者核查 DNS、TLS、网络策略及 Eastmoney 端点可达性；`trust_env=False` 是现有包的直连设置，本任务不擅自改代理、路由或运行时契约。修复环境后仍需完整 live 复测。
3. **若直连持续不可用，另立数据源/契约决策。** Owner 可决定是否设计并认证其它停牌数据来源或调整资格环境；这属于独立范围，不能以离线 Golden 或共同失败替代 live 成功，也不能直接豁免当前门禁。

**最终状态：** 历史日历项已关闭；Eastmoney 停牌 live gate 未关闭；`CONSUMER_QUALIFICATION = BLOCKED`、`RH3_A_RELEASE_GATE = BLOCKED`。停在 Owner Review，不批准生产 pin 更新、tag、发布或 RH3-B。

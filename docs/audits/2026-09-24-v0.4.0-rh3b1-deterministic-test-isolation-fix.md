## 1. Original failure and confirmed root cause

The failed tag-triggered workflow is [publish run 35873510512](https://github.com/joycoding2000/chstockdata/actions/runs/35873510512). The existing RH3-B close-out records the deterministic pytest gate failing with `tests/test_daily_bars_contract.py::test_vipdoc_volume_unit_is_shares`, specifically `Failed: mootdx must not be called`; the later publish steps were skipped.

The pre-fix test wrote `sh600519.day` (selected market path) beneath `tmp_path`, but its patched `get_config()` returned only `vipdoc_history_enabled` and `vipdoc_history_max_staleness_days`. The read path did not use the fixture directory:

1. `fetch_vipdoc_daily_bars()` calls `load_vipdoc_daily()` without an explicit `root`.
2. `load_vipdoc_daily()` resolves a missing `root` through `vipdoc_history_dir()`.
3. `vipdoc_history_dir()` derives the path from `vipdoc_history_dir`, or falls back to `{data_cache_dir}/vipdoc` / `~/.chstockdata/cache/vipdoc`.
4. The test's patched configuration omitted both directory keys, so the constructed `.day` file could not be found in a clean runner and routing reached the deliberately forbidden mootdx adapter.

This is a **CONFIRMED_DEFECT** in deterministic test isolation. No runtime defect was established.

### Pre-fix evidence

- With a fresh temporary `USERPROFILE`/home, no preloaded vipdoc tree, and vipdoc/cache environment variables removed, the pre-fix targeted test failed at `_must_not_run("mootdx")` with `Failed: mootdx must not be called` (1 failed). This reproduces the CI failure mechanism locally.
- Under the developer profile, `~/.chstockdata/cache/vipdoc/sh/lday/sh600519.day` existed and the same pre-fix test passed (1 passed). That confirms the previous local green result could be supplied by machine-local data rather than the test fixture. `.rh3a2-vipdoc` also existed locally, but the configured default resolution above points to `.chstockdata/cache/vipdoc`.
- The original run's raw log could not be downloaded during this fix review: `gh run view 35873510512 --repo joycoding2000/chstockdata --log-failed` returned HTTP 403 (`Must have admin rights to Repository`), and direct web retrieval returned a cache miss. The failure signature and workflow outcome above are taken from the existing RH3-B close-out; the isolated local RED run independently reproduced the failure.

## 2. Minimal correction

Only the existing test was changed in the fix commit `45f5234480355751696e9fde5ff4bfc063d2712a` (`test: isolate vipdoc volume unit contract fixture`). It now injects `"vipdoc_history_dir": str(tmp_path)` into the existing configuration stub.

The test keeps both `_must_not_run("mootdx")` and `_must_not_run("sina")`. It also now asserts:

- request success (`result.succeeded`);
- final provider and sole contributor are `tdx_vipdoc`;
- the only recorded attempt is `tdx_vipdoc` with `FETCH_SUCCESS`;
- returned `Volume` values equal the two 1000-share records written by this test;
- `volume_unit` is `shares` and metadata limitations include `volume_unit:shares`.

The fix commit changes one file by 8 insertions. The source change is limited to the configuration entry and these direct assertions; there is no new test framework or additional dependency.

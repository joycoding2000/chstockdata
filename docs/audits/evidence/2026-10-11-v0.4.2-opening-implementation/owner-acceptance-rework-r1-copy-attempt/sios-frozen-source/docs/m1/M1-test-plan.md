# M1 测试计划

## 1. 质量目标

M1 测试不证明策略赚钱。它证明：策略只能看到 T 时点可知的信息，真实使用 M0 内核，实验身份不可混淆，样本外不可被重复伪装，失败结果不会消失，智能体不能绕过验证器。

所有常规 CI 测试均离线、确定性运行，不使用系统时钟/网络。真实数据的接收/资格验证属于受控的证据关卡。

## 2. 测试层次

| 层次 | 目的 | 常规 CI |
|---|---|---:|
| 单元测试 | 合约、摘要、数据切分、产物/登记目录不变量、策略计算 | 是 |
| 组件测试 | 策略适配器 -> M0 决策上下文/引擎/指标 | 是 |
| 研究黄金用例 | ETF/股票的小型手算策略路径与报告 | 是 |
| 集成测试 | CLI、产物持久化、回放、崩溃/失败保留 | 是 |
| 资格验证 | 真实 ETF/股票数据快照能力与时点信息覆盖 | 受控 |
| 验收 | ETF/股票真实基础回测；符合条件者才有固定样本外 | 里程碑关卡 |

## 3. 策略合约用例

### M1-S01 — 合约形态与身份标识

断言每个策略有非空的编号/版本、有效的 SHA-256 实现/参数摘要、显式的子组合、回看窗口与决策节奏。修改规则文件或参数必须改变摘要。候选意图不允许包含实现/代码/数据快照摘要；研究运行清单必须包含它们。

### M1-S02 — 历史数据不足

少于所需回看窗口时返回 `StrategyEvaluation(status=NO_DECISION, reason_codes=("INSUFFICIENT_HISTORY",))`，不得将其与 100% 现金目标持仓或无原因的 `None` 混淆。

### M1-S03 — 确定性与输入顺序

同一 `DecisionContext` 重复调用，以及 K 线/标的池输入排序变化时，目标贡献的规范化字节/摘要相同。

### M1-S04 — 目标持仓有效性

权重非负、总和不超过 1、现金显式补足、ETF 属于 `CORE`、股票属于 `SATELLITE`，标的编号不从交易代码字符串猜测。

### M1-S05 — 策略隔离

静态 AST/导入检查禁止策略导入数据提供方、文件系统/网络客户端、系统时钟、回测执行/会计记账内部实现。核心/生产环境继续禁止导入研究模块。

## 4. 无未来信息用例

### M1-L01 — 未来 K 线蜕变测试

保持 T 及之前完全相同，任意改变 T+1 之后的开高低收量/公司行为/可交易性；T 时点的目标持仓/摘要必须字节级一致。

### M1-L02 — 同一次获取，不同可得性

复用 M0 时点信息语义：相同 `retrieved_at`、不同 `information_available_at` 的事实在 T 时点可见性不同；未知状态不可用。

### M1-L03 — 指标窗口边界

简单移动平均线、收益、突破、流动性窗口的最后一个观测值只能是 T；不得使用 shift(-1)、未来收盘价或样本外结束日的全区间统计。

### M1-L04 — 年度时点信息股票重构

每年末只读取该截止时点之前的记录并形成下一年度股票组；改变构建截止时点之后的上市/ST/流动性信息不改变该年度股票组摘要，新上市/新增流动性的股票可在后续年度按规则进入。

### M1-L05 — 预热期隔离

样本外运行器可以读取样本外起始日之前的预热期数据行，但这些数据行不进入样本外净值/指标的观测区间。

## 5. M0 内核连通

### M1-K01 — ETF 策略试飞

真实的绝对趋势代码通过适配器产生 `TargetContribution`，由 M0 引擎生成 T 日收盘计划数量、T+1 开盘成交、费用、净值与指标；策略不直接构造成交记录。

### M1-K02 — 股票策略试飞

相对强度/流动性策略使用当年度时点信息股票组，产生多个卫星子组合的目标贡献；M0 继续执行最小交易单位、全局资金充足性、T+1 交收、印花税与停牌规则。

### M1-K03 — 公司行为

策略分析价格与原始未复权数据的执行/会计记账相分离。现金分红/股数变动只由 M0 账本处理，策略不重复计入。

### M1-K04 — 拒单保留为证据

停牌、涨跌停、现金、交收等拒单进入实验报告，不能被运行器当作无交易而丢弃。

## 6. 实验日志与失败保留

### M1-E01 — 不可变产物与登记目录

每个运行/样本外目录与登记序号唯一；已有路径不得覆盖。修改任一旧产物都会使其自身的摘要校验失败。不要求前一事件哈希链。

### M1-E02 — 禁止覆盖

写入已存在的产物/报告路径必须失败。相同清单重跑使用新的尝试记录，但规范化结果摘要相同。

### M1-E03 — 失败运行保留

注入数据提供方故障、部分结果、内核异常、报告持久化失败；分别产生带类型的失败产物/登记条目，且不得产生“已完成/幸存”结果。

### M1-E04 — 尝试次数

每个参数组合、编译失败与被否决的运行都计入谱系尝试次数；汇总计数与不可变登记目录相等。

## 7. 身份标识与可复现性

### M1-R01 — 完整研究清单

缺少策略/候选意图/参数/标的池/数据快照/数据切分/基准/成本/指标/内核/代码/依赖中任一摘要时，运行失败即拒绝。

### M1-R02 — 变异矩阵

逐一修改上述字段，研究清单身份标识都必须变化；仅修改输出路径不改变身份标识。

### M1-R03 — 隔离重跑

同一冻结清单在两个临时目录中运行，比较目标持仓、订单、成交/拒单、账本、净值、指标、报告规范化摘要，必须完全相同。

### M1-R04 — 基准身份

看完结果后替换基准、把债券 ETF 当现金或改变基准再平衡，都会改变规格/清单，并使既有的样本外冻结不再匹配。

### M1-R05 — 预注册参数选择

两个以上参数变体同时 `BASIC_PASS` 时，验证器必须按候选意图中预注册的优先级列表取第一个；交换收益高低不能改变选择。缺少选择规则的多参数意图失败即拒绝。

## 8. 固定样本外与污染

### M1-O00 — 物理数据暴露

基础回测数据快照包含基础回测结束日之后的任何数据行即拒绝；冻结前样本外数据快照/路径/数据提供方原始目录树可读时，只能标记 `HISTORICAL_VALIDATION`。只有冻结后由数据物化器创建的冻结专属数据快照才可用于受控样本外。

### M1-O01 — 必须先通过基础回测关卡

没有 `BASIC_PASS` 产物时 `oos-freeze` 非零退出；`REJECTED_BASIC` 不得进入样本外；该资产类别可以以 `NO_OOS_ELIGIBLE_CANDIDATE` 结束。

### M1-O02 — 两阶段冻结的精确性

冻结绑定候选意图、策略字节、参数、标的池政策、请求范围、数据切分、基准、成本、指标；实际样本外数据快照摘要在物化生成后进入样本外运行清单。实际范围与请求不符，或任一冻结身份标识改变时，`oos-run` 必须拒绝。

### M1-O03 — 执行前先登记揭示

模拟样本外运行器崩溃；即使没有完整报告，区间也已登记为已揭示，不能再次当作未看过的样本外。

### M1-O04 — 谱系重叠

新策略版本使用同一谱系且样本外区间与已揭示区间重叠时，必须返回 `OOS_CONTAMINATED`；改变谱系显示名称不得绕过。

### M1-O05 — 唯一规范化裁决

同一冻结只能有一个规范化的样本外裁决；验证性回放只比较摘要，不新增幸存裁决。

### M1-O06 — 禁止根据结果修改关卡

幸存规则摘要是冻结的一部分；样本外之后编辑阈值不能重新计算为幸存。

## 9. 初步筛选与 CLI/智能体边界

### M1-C01 — 致命筛选原因

未来数据、M1 不支持的数据、未版本化的标的池政策、缺失基准、授权失败各自生成 `REJECTED_BEFORE_IMPLEMENTATION`。

### M1-C02 — 机器可读 CLI

`source-screen`、`screen`、`basic-backtest`、`select-oos`、`oos-freeze`、`oos-run`、`no-oos-eligible`、`verify` 成功时输出带版本号的 JSON；失败时以非零退出码结束，标准错误输出不含敏感信息。

### M1-C03 — 无绕过开关

CLI 解析器和集成测试证明不存在 `--force-pass`、`--ignore-contamination`、`--rewrite-artifact`。

### M1-C04 — AI 生成代码走同一关卡

以操作者为 `CODEX` 的测试夹具运行；它与人类操作者经过完全相同的验证器，操作者身份不影响裁决。另用一个真实外部网址/来源记录验证来源 -> 假设 -> 初步筛选，筛选否决同样通过该工作流测试。

## 10. 基准与报告

### M1-P01 — 同内核基准

买入持有/等权重基准使用相同的数据快照、交易日历、成本、执行/会计记账；不得直接拿复权收盘价的百分比与策略的净值比较。

### M1-P02 — 基础回测/样本外必备字段

报告包含复合年增长率、最大回撤、换手率、交易笔数、成本拖累、基准/超额、年度分解、关卡/拒单次数与全部摘要。

### M1-P03 — 仅年度/子区间

M1 必须输出年度/子区间分解；不得为完成 M1 创建正式的市场状态分类器/路由器。若提供可选的外部时点信息标签，切换标签不得改变目标持仓/订单/成交/输出摘要。

## 11. 数据资格验证关卡

- ETF 真实研究只限 M0 已批准的子类型/标的，并记录在线/录制式资格验证编号；
- 股票数据快照必须区分数据提供方故障、空结果与部分结果；
- 股票证券主数据/规则覆盖不完整、任一年度股票组少于 20、时点信息可得性未知，均失败即拒绝；
- 数据快照校验和、知识截止时点、原始/复权/公司行为一致性继续复用 M0 关卡；
- M1 不以“回测跑完”替代数据资格验证。

## 12. 常规 CI 与里程碑证据命令

实施完成后的最小命令集合：

```powershell
python -m pytest tests/research tests/integration/test_research_cli.py -q -p no:cacheprovider
python -m pytest tests/unit tests/contract tests/component tests/golden tests/integration -q -p no:cacheprovider
python -m ruff check src tests
python -m mypy --strict src/systematic_investing/research
```

预期：全部 M1 测试通过；M0 离线回归保持通过；Ruff 通过；新 `research` 包严格模式 mypy 通过。既有 M0 的 90 个全仓 mypy 发现项不在 M1 中顺手重构，也不得新增发现项。

真实里程碑关卡另外运行：

```powershell
python -m systematic_investing.research.cli verify --root var/research/experiments
python -m systematic_investing.research.cli acceptance-report --root var/research/experiments --output docs/reports/M1-acceptance-report.json
```

预期证据：产物/登记目录校验通过；ETF 与股票均有真实基础回测证据；每类资产都有规范化的固定样本外裁决或 `NO_OOS_ELIGIBLE_CANDIDATE`；所有失败/污染/尝试可计数；报告包含规范化摘要与 AI 来源试飞证据。

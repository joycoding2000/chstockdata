## mootdx + mcp resolver evidence

The clean combined install was run against the built wheel:

```text
pip install dist\\chstockdata-0.3.0-py3-none-any.whl[mootdx,mcp]
```

The resolver selected the current candidate families and reported:

- `mootdx 0.11.7`: `httpx>=0.25.0,<0.26.0`.
- Older resolver candidates down through `mootdx 0.10.0` also require an
  `httpx` range below `0.26.0` (the resolver enumerated the available 0.10.x
  and 0.11.x candidates).
- Supported MCP 1.x (`mcp 1.30.0`): `httpx>=0.27.1,<1.0.0`.
- The resolver also reached `mcp 1.0.0`, which requires `httpx>=0.27`; no
  MCP 1.x candidate has an `httpx` range intersecting mootdx's range.
- Final result: `ERROR: Cannot install chstockdata because these package
  versions have conflicting dependencies` / `ResolutionImpossible`.

An unconstrained preliminary clean install selected `mcp 2.2.0`; `pip check`
passed, but `build_server()` failed because MCP 2 renamed `FastMCP` and raised
the SDK migration error for `mcp.server.fastmcp`. This is why the package
metadata now declares `mcp>=1.0,<2` rather than falsely advertising MCP 2
compatibility.

## Remaining release risks

- The 288 visible Ruff findings are pre-existing/legacy debt outside the RH1
  structured and added-line gates.
- `mootdx` and MCP must remain separate environments until upstream `httpx`
  constraints converge; this is documented and metadata-enforced.
- Setuptools currently emits deprecation warnings for table-form `project.license`
  and license classifiers. Builds pass, but RH3 should modernize that metadata
  before the ecosystem deprecation deadline if desired.
- Live provider availability remains a runtime/observability concern and is not
  used as a PyPI publish blocker.

## Root causes

1. `actions/checkout@v4` used its default shallow history, while
   `scripts/check_rh1_static.py` must read the frozen RH1 commit for its diff
   and baseline checks.
2. The RH2 clean-install smoke checks asserted the literal runtime version
   `0.3.0`, which would block a correctly versioned RH3 release.
3. RH2 added `inspect` and `functools.wraps` to `mcp_server.py` in an order
   Ruff 0.16.6 considered unsorted. This was a real new Ruff finding, not a
   line-count or path-migration artifact.

## Checkout fix

The publish workflow now uses:

```yaml
- uses: actions/checkout@v4
  with:
    fetch-depth: 0
```

The static gate still uses the original frozen baseline SHA; history was not
removed from the comparison.

## Dynamic version consistency contract

`scripts/check_release_version.py` is a standard-library-only, independently
testable check. It enforces this chain:

```text
GITHUB_REF_NAME=vX.Y.Z
        ↓
project.version in pyproject.toml
        ↓
installed distribution metadata
        ↓
chstockdata.__version__
```

The tag must match `vMAJOR.MINOR.PATCH`, and the extracted version must equal
all three project/installed/runtime values. Installed module and distribution
paths must resolve under an isolated `site-packages` directory and outside the
source checkout.

The check runs before the build for tag/project agreement, then independently
after wheel installation and after sdist installation. The existing public
structured-export and console-script checks remain in the wheel smoke.

## Ruff 287 → 288 explanation

Using Ruff `0.16.6` against the exact commits:

| Revision | Full findings |
| --- | ---: |
| RH1 `d1cb63b` | 287 |
| RH2 `c23eec2` | 288 |

The one RH2 addition was:

```text
src/chstockdata/mcp_server.py:21
I001 Import block is un-sorted or un-formatted
```

RH2 introduced `from functools import wraps` before `import inspect`. The
minimal fix places `import inspect` before the `functools` import. The finding
is therefore classified as a **real newly introduced issue**, and it is now
resolved without a global ignore or a broad Ruff rewrite.

## Remaining release risks

- GitHub Actions runner behavior, protected `pypi` environment approval, and
  PyPI Trusted Publishing configuration were not exercised locally.
- The gate intentionally accepts stable `vMAJOR.MINOR.PATCH` tags. If RH3
  introduces prerelease tag formats, the tag contract and regression tests must
  be extended before using them.
- Dependency resolution and external provider availability remain environment
  concerns; neither is silently treated as a successful data result here.

## RH3 prerequisites

Before an RH3 release:

1. Bump `pyproject.toml` and `chstockdata.__version__` together in the RH3
   versioning change.
2. Create the matching `v0.4.0` tag only as part of the separately authorized
   release operation.
3. Re-run the deterministic tests, static gate, build, twine, wheel smoke, and
   sdist smoke against that version.
4. Confirm the GitHub `pypi` environment and Trusted Publishing registration
   before enabling the actual publish.

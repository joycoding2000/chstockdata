## Consumer canaries

### TradingAgents-AStock-Private — PASS (bounded compatibility, no delta)

The final refreshed source snapshot was tested twice, once with the 0.3.0
baseline wheel and once with the actual 0.4.0 candidate wheel. The import paths
were each under the corresponding isolated environment's `site-packages`.

The selected deterministic group reported **123 passed, 7 failed, 4
deselected** for both versions. All seven failures were identical: one existing
adjusted-bars source-label assertion and six failures in the newly present
untracked Phase 2 projection validation tests. These failures reproduce with
the 0.3.0 baseline and are not candidate regressions. A smaller offline data
layer/calendar subset also had identical baseline and candidate results.

Four calendar tests that intentionally fall back to live Sina were excluded
from the refreshed run. No production realtime-snapshot call site was found;
the network-marked live smoke test was not run. The existing dependency range
still excludes 0.4.0, so adoption requires a separate consumer dependency
update even though the direct wheel compatibility canary showed no delta.

### systematic-investing-os — BLOCKED / NOT VERIFIED

The consumer's deterministic suite reported `91 passed` with both the existing
source setup and the candidate environment, but those tests mostly exercise
injected provider stubs. A direct call through the real
`LibraryChStockDataClient` with the candidate wheel was rejected by its exact
0.3.0 version guard, which requires contract, ETF, golden, and smoke
requalification before accepting a new provider release.

This is an intentional frozen M1 qualification boundary, not a 0.4.0 package
regression. M1 was not changed. This consumer blocks RH3-A acceptance until its
owner separately authorizes and completes that requalification.

## Limitations and remaining work

- BSE delisting coverage is not implemented.
- IPO and full listing-lifecycle eligibility are out of scope; the PIT guard
  applies only the recorded delisting effective date to requests on or after
  that date, not a complete historical point-in-time database.
- Legacy APIs remain supported; structured APIs are additive.
- `mootdx+mcp` together remains unsupported.
- Requalify and explicitly update the frozen `systematic-investing-os` M1
  provider pin before claiming that consumer accepts 0.4.0.
- Update the TradingAgents dependency range separately before adoption.
- Verify PyPI Trusted Publisher configuration before any RH3-B action.

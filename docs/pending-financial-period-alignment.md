# 财务报告期口径对齐 — 交接说明（来自 TradingAgents-Astock 私仓 P2-5）

- **状态**: 待实施（交接于 2026-09-14）
- **优先级**: 中（不影响接口可用性，影响读数正确性与上游报告的可信度）
- **提出方**: 私仓 TradingAgents-Astock-Private，CR `docs/releases/v0.6.0/change-requests/CR-V050-ACCEPTANCE-FIXES.md`（P2-5 遗留项）
- **输入**: v0.5.0 线上真实用户验收（2026-09-14）P2-5——同一份报告对同一报告期给出互相矛盾的同比数字

## 1. 验收现象（为什么做这件事）

2026-09-14 晚间线上验收（3 只小盘股完整跑通），同一份报告内出现未经裁决的矛盾同比：

| 股票 | 数据面读数 | 新闻/情绪/政策面转述 |
| --- | --- | --- |
| 300452 山河药辅 | 营收同比 **+0.11%**、净利同比 **+0.04%** | 营收同比 **+10.8%**、净利同比 **+3.39%** |
| 002337 赛象科技 | 净利同比 **-0.40%** | 净利同比 **-37.76%** |

LLM 层如实披露「两种说法打架」是正确行为；问题在**输入端**：数据面给出的同比数字本身口径存疑（差一个数量级，很像「累计 vs 单季」或「同期比基期不同」），且 mootdx 快照金额没有任何报告期标注，模型无从对齐。

框架侧（私仓 commit `f1b142b`）已做的**读数侧缓解**：同比读数标注 `（来源：X 工具）` + 追加「同比口径说明」边界行。本仓要做的是**数据侧根因**：把报告期口径对齐、把存疑的同比源头修掉或自算。

## 2. 链路事实（代码定位，接手免考古）

以下行号基于本仓 HEAD `da33420` 的 `src/chstockdata/a_stock.py`：

1. **mootdx 财务快照（无期标注）**——`get_fundamentals`（:2660）内 `_mootdx_call("finance", symbol=code)` 段（约 :2722-2790）：渲染 F10 公司概况最新一期**绝对值**（Revenue/Net Profit/EPS/ROE derived 等），**不输出任何报告期**。注释里已实测金额字段是 0.1 元口径（600519 对齐新浪 2026-06-30 期营收），说明快照期≈最新报告期，但代码没有把这个期写出来。TDX 7709 F10 finance 返回里是否有报告期字段**未确认**。
2. **新浪三表（有报告日/公告日，同比来自 `item_tongbi` 透传）**——`_get_financial_report_sina`（约 :2895-3004）：`CompanyFinanceService.getFinanceReport2022`，每期 `{YYYYMMDD: {data: [{item_title, item_value, item_tongbi, ann_date}]}}`。`item_tongbi` 在 :2962-2963 原样存为 `{标题}同比` 列。
3. **结构化指标（唯一带 report_period_end 的输出）**——`get_free_financial_indicators`（:3113-3320）：取三表**共同最新报告期**，输出 `report_period_end` / `announcement_date` / `statement_announcement_dates`，其中：
   - `营收同比增长率` = `raw_yoy(income_row, "营业收入同比", "主营业务收入同比")`（:3310，即新浪 `item_tongbi` 原样透传）
   - `净利润同比增长率` = `raw_yoy(income_row, "净利润同比", ...)`（:3311）
   - 对比：ROE 是自己算的（:3245-3266，年报用净利润/平均归母权益，季报用 TTM，基期明确）——说明作者对 `item_tongbi` 也未敢直接用于 ROE。

**核心疑点**：新浪 `item_tongbi` 的口径**未经验证、接口未文档化**——它是「本期 vs 上年同期（同期比）」还是别的基期？是累计口径还是单季？300452 的 +0.11% 与官方中报口径差一个数量级，提示透传不可信。

## 3. 任务拆解

### T1 核对并修复 `item_tongbi` 同比口径（高优先）

- 方法：取 2-3 只有官方披露数字的样本（建议 300452 / 002337 / 600519），用新浪三表原始 `item_value` **自算同期比**（`item_title` 本期值 ÷ report_list 中上年同期行的同项目值 − 1；report_list 拉了 20 期，足够取到上年同期），与 `item_tongbi` 逐项对比。
- 若不一致：`get_free_financial_indicators` 的同比改为**自算同期比**（与 ROE 同样的基期推导方式），不再透传 `item_tongbi`；`{标题}同比` 列要么删除要么改名注明「新浪原始口径，未采信」。
- 若一致：把对比证据（股票/期次/item_value/item_tongbi/自算值）记录到本文档附录，问题归因于新闻转述口径，T1 关闭。
- 附带确认：新浪该接口的同比是**累计口径**（中报=H1 累计）还是单季，写进输出注释。

### T2 mootdx 财务快照补报告期标注（中优先）

- 先确认 TDX F10 finance 返回是否携带报告期字段（全字段 dump 一只股票看列名）。
- 有 → 输出报告期；没有 → 用新浪三表最新公告期作「快照期参考」标注（快照期≈最新报告期已有 600519/000858 实测佐证），并在输出里显式披露「参考期、非快照自带」。
- 底线：绝对值读数必须带期，不能与带期数字并列裸奔。

### T3 同比输出补基期语义（低优先，随 T1 顺手）

- `get_free_financial_indicators` 的同比行写明基期（`report_period − 1 年`）与口径（累计/单季），例如 `- 营收同比增长率: +10.80%（2026H1 累计，较 2025H1）`。

### T4 版本与上游联动

- 按 `CHANGELOG.md` 惯例发 0.2.x（不破坏 0.2 契约优先；若 T1 决定删 `{标题}同比` 列，属行为变更，CHANGELOG 注明）。
- **兼容性约束（重要）**：私仓框架按稳定中文标签读数，`营收同比增长率`/`净利润同比增长率`/`营收同比增速`/`净利润同比增速` 等标签名**不要改名**（框架 `web/../fundamentals_data_plane` 的 `_PUBLIC_FUNDAMENTAL_LABELS` 与证据 Envelope `report_period_end`/`announcement_date` 字段都依赖现状）；标签值格式 `+10.80%` 保持。
- 私仓 pin 为 `chstockdata>=0.2.0,<0.3`，本修复发版后框架侧升 pin 即自动消费，无需框架改代码。

## 4. 验收标准

1. T1 有 oracle 对比证据（官方披露 vs 修复后输出），300452 最新中报的营收/净利同比与巨潮/公司公告口径一致。
2. `get_fundamentals` 的每行金额读数带报告期（或显式参考期披露）（T2）。

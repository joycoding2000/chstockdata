## Historical candidate record (2026-10-09)

The content below is the local release candidate record as of 2026-10-09,
kept unchanged as a historical judgment.

This local candidate prepares the approved VIPDOC Price Scale correctness fix
for consumer qualification. The v0.4.1 baseline is commit
`88f9b6677ade4a6ed280c865e6cf1edaf625a49f`; the approved fix is commit
`9fd011c5e1f491ec02197e91aa3eb72c1b257610`. Release preparation changes only
version metadata and release notes, preserving the approved implementation
and price Golden contract.

### Price scale correction

Qualification matches the filename's market and six-digit ASCII code, with
case-insensitive market letters and the `.day` filename boundary:

| Qualified category | Raw OHLC multiplier |
| --- | ---: |
| SH60, SH68, SZ00, SZ30 | 0.01 |
| SH50, SH51, SZ15, SZ16 | 0.001 |

Qualified fund prices correct the previous tenfold scale error. Derived
`pre_close` follows the corrected preceding close before date-window
filtering. The qualified stock conversion remains compatible with v0.4.1;
volume and amount units are unchanged.

The FIX_ONLY precision repair divides raw qualified fund integers by 1000
directly instead of multiplying by the floating-point reciprocal. This keeps
the float API and derived `pre_close`, while avoiding tails such as
`3937 * 0.001 == 3.9370000000000003` under the consumer's exact Decimal contract.

BJ, SH58, SZ18 and all other unqualified categories or filenames retain the
legacy division by 100. Legacy compatibility does not certify their price
precision or extend the qualified category set. The existing legacy text/CSV
renderer retains its two-decimal price presentation.

### Scope and qualification boundary

The 2026-10-09 release task also corrects suspension source semantics:
historical/future suspension requests fail closed through the existing
failed_structure envelope; current-day future-start records cannot block
trading, and records ending before today are no longer treated as suspended.
Derived tradability requires an explicit boolean negative before returning
tradable=True. No new
Provider, architecture or dependency changes are included. Frozen SIOS/M1
data, production pins and admission rules remain unchanged. The original
v0.4.1 release records and existing audit conclusions are preserved.

The local wheel and sdist require consumer qualification against the fixed
consumer snapshots and established version baselines. Previous v0.4.1
qualification evidence does not qualify the changed price output by itself.
Local package checks do not constitute consumer or formal release Gate
acceptance.

The 2026-10-09 Owner request supplies conditional end-to-end release
authorization. The historical capability required by the frozen SIOS
consumer remains a release blocker: truthful unavailability does not replace
that contract. No v0.4.2 tag or publication is permitted while this Gate fails.
See [concentrated closeout audit](../audits/2026-10-09-v0.4.2-release-closeout.md).

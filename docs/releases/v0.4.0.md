# chstockdata v0.4.0 release candidate

This document describes the v0.4.0 candidate. It has not been published to
PyPI; publication requires separate RH3-B Owner authorization.

## What is included

Six additive structured entry points are available:

- `fetch_realtime_quotes`: routes quote providers and returns typed status,
  attempts, and metadata.
- `fetch_daily_bars`: routes daily-bar providers with normalized records and
  coverage details.
- `fetch_trading_calendar`: returns structured calendar results and
  capability observations.
- `fetch_suspension_info`: returns a structured full-date suspension snapshot.
- `fetch_delisting_status`: returns separate structured SSE and SZSE status
  observations.
- `fetch_tradability`: derives a conservative result from covered calendar,
  delisting-date, and suspension facts.

`FetchResult`, `FetchMetadata`, and `FetchAttempt` represent the request
outcome, provider/routing metadata, and per-provider attempt provenance.
Capability-scoped health records observations independently for each
provider capability.

The delisting-date guard applies a recorded effective date only to requests
on that date or later, preventing a later delisting record from leaking into
an earlier request. It is a date guard over available records, not a complete
historical point-in-time database or a full listing-lifecycle model.

Existing legacy APIs remain supported, including the established stock-data,
realtime snapshot, calendar, suspension, and delisting call shapes.

## Known limits

- BSE delisting coverage is not implemented.
- IPO and complete listing-lifecycle eligibility are out of scope.
- `mootdx` and `mcp` cannot be installed together because their `httpx`
  constraints conflict; use separate environments.
- Legacy APIs remain supported alongside the additive structured surface.
